# 瓷砖墙功能与验收指南

瓷砖是有网络身份、物理显示输出和输入能力的终端。Hook Unit、Live 会话和
Art 内容是显示对象，独立于终端。当前已有控制、呈现和交互实现；完整产品验收
仍有下列 19 项未关闭，不能从代码存在或本机测试通过推断双机交付完成。

## 使用与所有权

Loom daemon 管理终端注册、墙面布局、内容位置、授权及恢复；Loom 桌面端的设备
管理页提供墙面管理。关闭管理窗口不应停止 daemon 与终端上的显示和交互。
Hook 终端的启动、配对、物理输出选择、媒体模式和输入限制见
[终端指南](../../Hook/docs/TILE_TERMINAL.md)。

普通 Hook 捕获 Unit 提供“发布到 Loom”“停止发布”和收回操作权入口。
同一内容可跨屏或在多个位置显示；改变位置、关闭参数面板或移除单个显示位置
不应重复启动采集、Art 或源程序，也不应关闭其他位置仍在使用的来源。
Live 来源恢复保持原 origin、设备、capture 和公开 Live ID；结束的捕获或
不可恢复的来源必须明确报告，不能重放旧输入。

每块终端可以独立工作或加入墙面，支持多面墙和逐块调整布局。终端不能被假定
拥有通用 CPU、GPU 或应用运行环境；声明能力必须与实际支持的解码、显示和输入
一致。能力声明不授予权限，也不证明端到端帧率。专用硬件制造不在软件范围内。

## 功能合同

- [几何与所有权](../protocol/WALL_PROTOCOL.md)：端点、墙面、来源与内容位置独立；
  使用一致的布局版本做终端像素、墙面和源坐标转换；半开区间保证接缝命中唯一。
- [控制 API](../protocol/WALL_CONTROL_API.md)：配对设备注册、布局 CAS、持久化、
  呈现租约和应用回执。终端缺席不删除布局或源内容。
- [Live 输入](../protocol/WALL_INPUT_API.md)：身份、焦点、可靠序列、操作租约和回源权限。
  不给终端管理员凭证、源程序路径或私有 GPU 句柄。
- [Art Surface](../protocol/WALL_SURFACE_API.md)：复用实例、附件、资源与 action 授权；
  保持确认、取消、正式结果与临时预览的边界。
- [显示控制](../protocol/WALL_PRESENTATION_API.md)与
  [物理屏幕识别](../protocol/WALL_IDENTIFICATION_API.md)：冻结、黑场、恢复和限时识别
  必须同步管理输入状态、回执与租约。
- [时间与媒体](../protocol/WALL_TIMING_MEDIA.md)：完整场景准备/生效、公共时钟、
  raw BGRA/PNG 能力协商、有界编解码与帧队列。媒体不进入 Surface 状态或布局存储。

输入丢失焦点、终端断线、来源关闭、布局替换、时钟失效或权限撤销时必须释放按键、
按钮和租约。跨屏手势无法确认交接身份时安全取消。当前声明 pointer/wheel/keyboard，
不能将未实现的原生多点触摸或笔输入广告为可用。

## 尚未完成的验收

以下保留原任务 ID 与全部 19 个开放条件。已实现的代码仍需对应运行证据；
纯文档清理不改变验收状态。原计划 53 项中的 34 项阶段证据可从 Git 历史恢复。

### TW-04：终端与输出（4 项）

- [ ] 枚举、识别并绑定稳定的物理显示输出；支持每设备多个输出 ID。
- [ ] 在选定输出上建立显示窗口，处理像素尺寸、DPI、旋转、热插拔及输出丢失。
- [ ] 按墙面布局显示测试图，跨接缝裁剪准确，控制界面不混入输出画面。
- [ ] 上报实际终端能力；不支持的媒体/输入组合有结构化原因。

需要两个独立终端接入同一 Loom，在指定屏幕显示墙面的不同区域，并确认退出只
清理各自拥有的资源。首次配对并发和真实多输出环境也应纳入运行检查。

### TW-05：呈现与来源复用（2 项）

- [ ] 低能力终端采用协商后的可消费画面通路，不能强制其执行应用或任意脚本。
- [ ] 限制解码尺寸、并发、帧队列与缓存；慢终端不能无限堆积数据或拖住其他终端。

### TW-06：交互与操作权（2 项）

- [ ] 跨瓷砖手势有明确指针交接及捕获 owner；不可确认的交接安全取消，不能猜测另一用户的手指身份。
- [ ] 多人操作不同内容互不干扰；同一传统应用的竞争有可见操作权和交接，不能混入两套按键状态。

### TW-07：恢复（1 项）

- [ ] Loom 重启恢复持久化布局，重新建立授权及可恢复来源，显式报告不可恢复的源会话。

### TW-08：调度、延迟与资源（5 项）

- [ ] 定义布局/场景的准备与生效时刻，终端报告已应用版本。
- [ ] 定义媒体时间戳、时钟估计、缓冲、迟到帧和不同刷新率策略。
- [ ] 用同一动态内容跨屏验证帧选择及显示时间差；不从发送计数推断物理同步。
- [ ] 测量输入到源效果/显示反馈延迟，以及各进程 CPU、内存、句柄和媒体流量。
- [ ] 运行有界压力和断线测试，记录规模及硬件能力；不把专用硬件 Frame Lock/Genlock 写成软件已经保证的能力。

### TW-09：门禁与联合交付（5 项）

- [ ] 两仓相关 formatter、聚焦行为测试、Rust 编译/前端类型检查和有效行数门禁通过。
- [ ] 两仓依赖安全要求及发布合同按实际改动执行；不伪造批准、签名或干净源码状态。
- [ ] 两个独立显示终端的真实局域网验收，覆盖图片/Live/Art、跨屏交互、断线和无头运行。
- [ ] 用实际发布二进制重复关键联合验收，记录进程路径、产物摘要、结果与限制。
- [ ] 分别复核两仓 Git 状态和 `git diff --check`，完成逐项证据审计。

## 运行验收范围与证据限制

普通 GUI 来源联合运行须覆盖真实捕获、打开 Unit 参数、从可见按钮发布、放置到墙面、
回源交互、停止发布和来源关闭，并确认 capture、Live ID 与源应用状态连续。
daemon/输出重启、断网、撤权、已关闭来源和并发停止分别验证。普通 GUI 捕获基线
或通过测试入口发布的探针结果，不能替代可见产品入口的联合验收。

raw/PNG 模式、混合图片/Live/Art 场景切换、时钟过期与重建、快速布局更新、帧选择、
慢解码/慢网络隔离和可见操作权竞争仍需实际运行。两台实体电脑的局域网测试须包含
跨屏、不同内容并发交互、同源竞争、手势交接、恢复与无头运行；单机模拟不能补足。

完整 600 秒动态画面、真实输入、CPU、私有内存、句柄、worker 和流量长测仍未通过。
历史两次运行分别在第 8 次和第 98 次输入超时提前失败：前者原因未确认；后者轨迹
显示共享桌面外部输入可能触发 `pointerleave` 取消。后续运行需预留约 12 分钟不操作
共享桌面键鼠，保留 `pointerleave`、generation 和租约安全语义，不重放失败点击。
短窗口资源观察不能补足完整长测、断线压力或多终端资源隔离。

同源跨屏显示时间差、输入到真实显示反馈延迟、NIC 媒体流量和硬件配置需要实测。
`wall_live_stats`、`data-media-stats`、源效果采样或发送计数不能替代显示扫描或网卡测量。
当前没有 Frame Lock/Genlock 保证。

2026-09-19 的本机源码测试已覆盖 Hook 墙面逻辑及 Loom 协议、store、HTTP 路径，
因此旧交接中“全部行为测试等待执行”的说法已过时。这些证据没有完成真实 GUI 来源
联合运行、双机 LAN、Linux、物理同步、600 秒长测或完整发布包联合验收。
