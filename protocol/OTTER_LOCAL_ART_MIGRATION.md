# Art JS 向 Otter 单侧执行迁移

## 当前范围决定（2026-11-04）

用户取消全部旧协议、旧模式、旧程序兼容，配套软件同步升级最新架构。不再为新旧互通建立协商、回退或适配阶段；下文冲突的历史迁移流程失效。当前唯一准备合同是[Local Art v3](LOCAL_ART_EXECUTION.md#当前唯一准备合同v5382026-11-04)，功能、安全、离线及真实产品验收要求保留，不启动Loom原生迁移。

状态：2026-10-28 已确认目标；本文件是迁移边界与待实现合同，不是新 wire 协议或完成证明。
用户已授权修改独立 Loom 仓库必要源码；本次只先统一计划，不提交、推送、发布或部署。

## 已确定方向

- Art 保留 JS 源码及必要资源包；由 Otter 所属 QuickJS 执行设施运行，不要求终端用户编译 Rust 插件。
- Loom 保留包、版本、依赖、授权管理与服务能力，不再作为这部分 Art JS 的另一个执行端。
- 轻量事件、参数变化和预览在 Otter 本地闭环，真正远程能力通过异步服务合同调用。
- 已缓存所需包/资源且已有授权仍有效时，本地功能可离线运行；缓存不等于永久许可。
- 默认状态按 Otter 工作区/Art 实例独立；显式共享与续接另走合同，不因同连一个 Loom 自动共享。
- 本地 JS 执行不自动迁移全部持久状态或正式结果 owner，也不把 Loom 变成 Otter 内部模块。

## 当前基线不得无声变义

[现有协议](README.md) 的 hook/surface v1 仍定义 Loom execution 和正式结果提交。
JavaScript source 不属于既有 Surface 控制消息；本文件不授权往旧 JSON 字段塞源码。
现有客户端、transport/authorization、confirmation、resource release 和 cancellation 语义继续有效。
未来升级必须显式协商客户端执行能力、协议/SDK/包版本；不支持的组合明确拒绝或提示升级，
不回退为 Loom/Otter 双侧执行同一 Art JS，不声称其他 Loom 客户端自动具备 QuickJS。

## 下一合同切片需要明确

| 边界 | 必须确定并测试的规则 |
| --- | --- |
| 包分发 | 发布者、精确版本/digest、来源信任、依赖、SDK 范围；控制消息不承载大型源码/资源 |
| 获取与缓存 | 认证与资源授权、路径/解包/容量限制、完整性、原子安装、可恢复升级；不泄漏服务端私有路径 |
| 执行授权 | 安装不等于启用；精确包/设备/能力范围、有效期、撤权、离线边界与受控宿主接口 |
| 实例 | 工作区/实例/包版本/请求代际绑定；停用/升级/退出后旧回调和结果无权提交 |
| 服务调用 | 异步、取消、进度、超时、并发和背压；普通本地事件不转换为逐事件远程 Art execute |
| 状态与结果 | 独立本地状态、显式共享、预览与正式输出区分；owner/原子提交/幂等与恢复逐项设计 |
| 生命周期 | Otter 完全退出不把 JS 转交 Loom；隐藏驻留与远程已提交服务任务另行明确 |

不能只复用普通设备登录就授予本地任意执行、文件或网络权限；敏感确认由宿主管理。
QuickJS 中断和 Windows Job 不是完整安全沙箱，实际隔离与同步原生调用预算必须验证。

## 实施顺序与退出门

1. 核当前包、授权、执行、Surface 与资源 owner，先写版本化合同和负例，再改生产接线。
2. 一个真实源码 Art 完成 Loom 管包→受控获取→Otter 加载→本地预览→异步服务→正式结果链。
3. 分别验证本机/远程 Loom，证明本地交互不依赖逐事件网络往返，JS 实例仅位于 Otter 执行设施。
4. 补停用、升级/回滚、离线、撤权、退出、异常包/越权/资源上限及旧实例晚到结果测试。
5. 迁移涉及的现有能力包可升级，但不以删除功能替代迁移；新旧协议边界和其他客户端回归明确。

Otter 总计划在其独立仓库 `docs/development/WINDOWS_NATIVE_REVISED_PLAN.md`。
两个仓库分别记录源码、测试与产物身份，不以单侧通过宣称联合验收。
本文件不宣称新 SDK、包 schema、授权或本地 Art execution 已实现。
